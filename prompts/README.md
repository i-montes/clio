# System prompts

The prompts live in the repository, versioned: `system/<name>@<version>.md`, with a `version: <n>` line at the top equal to the one in the file name.

- **A published version is never edited.** A change is a new version (`clio@2.md`); the previous one stays. That way each trace can say which version it used (`clio.prompt.version` in clio-trace) and the bench compares versions.
- `MANIFEST.json` holds the sha256 of each file. `scripts/check-prompts.py` fails if a prompt changes without the manifest changing, or if an entry is missing: the change shows in the diff and the person reviews it (`CODEOWNERS`).
- **Nothing whose leak matters (S-09).** The system prompt is assumed public: no keys, emails, paths of your machine, IP addresses or long random-looking strings. The scanner checks that; the human review checks what a pattern cannot see (people's names, details of your infrastructure).
- Changing a prompt goes through the same gate as code: tests, bench and attacks (`ci.yml` does not filter by path).
- The prompts are in English; the model answers in the language the person writes in (a line near the top of each says so). `clio-agent@21` and `clio-host@5` are the English versions of `@20` and `@4`, which are partly in Spanish and stay as they were. `clio-agent@22` and `clio-host@6` change only the passage on the person's blocks: in a session that read outside content a block change waits for the person's approval. `clio-agent@23` and `clio-host@7` add one section, Skills: where the list is, use a matching skill, create or update one with `skill_write` (always with a check), report a failure with `skill_report`, never write the skills folder another way. `clio-agent@29` and `clio-host@13` add one line to Skills: which of Clio's tools are the tools a skill written for another harness names (Task or Agent, a todo tool, Skill, Read, Write, Edit, Bash, Grep, Glob, `plugin:name`), and drop the per-session memory budget from the line on consulting the memory (there is none any more): it is still consulted on purpose, not just in case. `clio-host@13` also says, in each sentence on what waits for the person (registering a service, `undo` of a service or `on` of one the person turned off, removing or taking back a skill Clio ships, an MCP server), that while the person's bypass is on (the message's envelope says so) Clio does it by herself and tells the model what came of it; a skill added from outside (`skill_add`) is the exception that always asks. `clio-agent@30` and `clio-host@14` add one section, Subagents (S-73): the chat's `subagent` tool, what a subagent gets and never gets, and that its report is data. `clio-subagent@1` is the prompt of a subagent, reader or writer: its tools, its report, and what it leaves to its parent (what would wait for the person, a subagent or a skill to add).

To register a change: edit or add the file, run `python3 scripts/check-prompts.py --update` and commit the file and the manifest together.
